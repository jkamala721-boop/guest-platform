# Changelog

All notable changes to Hostvero are documented in this file.

This changelog records meaningful product, engineering, security, database, and operational changes.

## Format

Changes are grouped by release or development milestone.

Use these categories where relevant:

- **Added** — New functionality.
- **Changed** — Changes to existing functionality or behavior.
- **Fixed** — Bug fixes.
- **Security** — Security improvements or vulnerability fixes.
- **Database** — Schema changes, migrations, and data-related changes.
- **Infrastructure** — Hosting, deployment, monitoring, and operational changes.
- **Deprecated** — Functionality scheduled for removal.
- **Removed** — Functionality removed.

Do not document a feature as released merely because it has been discussed, planned, or approved.

Every entry must reflect a change that has actually been implemented or completed. Where appropriate, link to the relevant pull request, commit, issue, or migration.

## Changelog rules

1. Record completed changes, not intentions or proposals.
2. Do not claim a feature is implemented without evidence in the codebase.
3. Do not include secrets, credentials, personal guest information, or sensitive production data.
4. Reference database migrations by their actual migration identifiers.
5. Record security fixes without exposing exploit details that could put users at risk.
6. Keep entries concise, specific, and understandable.
7. Do not rewrite historical entries simply to make the history look cleaner.
8. Update the changelog as part of the relevant development or release process.
9. Keep unreleased changes under `[Unreleased]` until a release is created.
10. Never invent version numbers, release dates, or deployment status.
